AC 4i.7.4 README - Equal-weighted festival average rise ratios
AC 4i.7.4 交付说明 - 节日等权平均涨价比例
================================================================

1. What this commit does / 本次提交内容
----------------------------------------------------------------
中文：
- 新增逐节日平均涨价比例计算。主 avg_rise_ratio 使用完整窗口中
  rise_status=rise 的商品涨幅等权平均，作为 US 4i.6 的唯一换算依据。
- 同时输出 avg_net_change_ratio，对所有 status=ok 的商品计算净变化均值，
  仅作诊断，不替代主比例。
- 州级统计按本州商品等权；节日级统计先按 item_code 汇总跨州值，再在
  唯一商品之间等权，避免多州商品重复加权。
- 输出 median_rise_ratio、price_item_count、eligible_item_count、
  rising_item_count、flat_or_fall_item_count、total/remaining/excluded
  observation count、exclusion_ratio 和 sample_status_counts。
- 窗口未就绪的显著节日输出 ratio_status=window_not_ready，不编造比例。
- 新增离线脚本 database/compute_festival_rise_ratios.py，读取
  festival_price_stats.json，输出 festival_rise_ratios.json。
- 全量结果：8 个显著节日；75 条节日-州属记录；7 个节日比例可用；
  thaipusam-2026 因 3 个州均为 no_rise，状态为 window_not_ready。
- 本提交只交付离线 JSON 数据，不修改 PostgreSQL schema，不实现 API 或
  前端页面。

English:
- Adds festival average rise ratio calculation. The primary avg_rise_ratio is
  the equal-weighted average rise of items with a complete window and
  rise_status=rise, and is the sole conversion basis for US 4i.6.
- Also outputs avg_net_change_ratio over all status=ok items as a diagnostic
  net-change measure; it does not replace the primary ratio.
- State-level rows use equal weighting across items in that state. Festival-level
  rows first aggregate each item_code across states, then use equal weighting
  across unique items, avoiding repeated weighting of multi-state items.
- Outputs median_rise_ratio, item counts, rising/flat_or_fall counts,
  total/remaining/excluded observation counts, exclusion_ratio, and
  sample_status_counts.
- Significant festivals with no ready key window are returned as
  ratio_status=window_not_ready instead of being omitted.
- Adds the offline script database/compute_festival_rise_ratios.py, which reads
  festival_price_stats.json and writes festival_rise_ratios.json.
- Full result: 8 significant festivals; 75 festival-state rows; 7 festivals
  with usable ratios; thaipusam-2026 is window_not_ready because all three
  state windows are no_rise.
- This commit delivers offline JSON data only. It does not change the
  PostgreSQL schema and does not implement an API or frontend page.

2. How to verify / 验证方式
----------------------------------------------------------------
中文：
- 单元测试：在 backend 目录运行
  python -m pytest tests/test_festival_price_stats.py
    tests/test_festival_analytics.py -q
  预期 43 项通过。
- 全量运行：
  python database/compute_festival_rise_ratios.py
    --price-stats <festival_price_stats.json>
    --out <festival_rise_ratios.json>
- 预期结果：8 个显著节日、75 条节日-州属记录、7 个 ratio_status=ok、
  1 个 window_not_ready 节日。
- 重点检查：
  thaipusam-2026 应为 window_not_ready；
  avg_rise_ratio 与 avg_net_change_ratio 必须分别输出；
  ratio_status=ok 时 rising_item_count 不得少于 30；
  exclusion_ratio 必须在 0 至 1 之间。

English:
- Unit tests: from the backend directory run
  python -m pytest tests/test_festival_price_stats.py
    tests/test_festival_analytics.py -q
  Expect 43 passing tests.
- Full run:
  python database/compute_festival_rise_ratios.py
    --price-stats <festival_price_stats.json>
    --out <festival_rise_ratios.json>
- Expected result: 8 significant festivals, 75 festival-state rows, 7 rows with
  ratio_status=ok, and 1 festival with window_not_ready.
- Key checks:
  thaipusam-2026 must be window_not_ready;
  avg_rise_ratio and avg_net_change_ratio must both be present;
  ratio_status=ok must not have fewer than 30 rising items;
  exclusion_ratio must be between 0 and 1.
